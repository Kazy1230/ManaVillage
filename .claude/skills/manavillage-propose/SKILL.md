`web/content/planning/common.md` の 2-1 と、対象の科目の文書(英語学習 `workflow.md` / 日本語学習 `japanese/workflow.md`)に従う。**記事の本文は書かない。**

Kaz が科目と本数を言っていればそれに従う。言っていなければ、各科目3テーマ。`web/` でコマンドを実行する。

1テーマごとに:

1. **抽出**: 英語学習・日本語学習は `node scripts/pick-topic.mjs <english|japanese>`(在庫から無作為。Kaz の確認はいらない)。**IT・哲学・科学・人間関係は、在庫がない**ので、`planning/<科目>/topic-map.md` の「次に書く候補」から無作為に選ぶ(Kaz がテーマを指定したら、それに従う)。選んだ候補は、topic-map の記事一覧に `proposed` で行を足し、候補の一覧から消す。topic-map を読んで重複するなら、在庫の行を `skip`(`note` に理由)にして引き直す
2. **調べる**:
   - 主キーワードで実際に検索し(日本語学習は英語で)、上位の記事は何か、何が足りないかを確かめる。上位が大手や公式で埋まっていて、切り口を変えても勝てない語なら、`skip` にして引き直す
   - 根拠にできる出典(研究の要旨、文法なら科目の文書が認める資料)を、**原典を開いて確認**する。確認できた内容と URL を書く。確認できなかったものは、そう書く
   - **体験談**: 構成案で体験談を入れたい所が出たら、personal-brain の `search_persona`(theme: learning。必要なら creative、work)と `content/materials/` で、その体験が記録にあるか検索する(`common.md` 2-1b)。**記録にあれば**、記録の内容を示す(細かい事実を足さない)。**なければ、作らずに、Kaz に質問する**(下の「体験談の質問」)
   - 同じ科目の直近5本の見出しを読み、似すぎない構成にする(記事が少ないうちは、あるだけ)
3. **提案を書く**(著者が雪菜の記事なら、その旨と、雪菜の口調で書く予定であることも): `web/content/planning/proposals/<slug>.md`(日本語学習は `japanese/proposals/`)。書くこと: 仮タイトル案2〜3個、主キーワード、検索意図、想定読者(日本語学習はレベル)、勝てる理由(上位記事にない情報を最低1つ)、概要(3〜5行)、構成案(決まった型は使わない)、各見出しで使える具体例・例え話・小ネタの案、**使えそうな体験談の候補(記録にあるもの。記録にないものは、Kaz への質問として別に)**、出典(確認済み)、サムネと図の案、内部リンクの候補
4. **登録**: 在庫の行を `selected` にして slug を書く。topic-map に `proposed` で行を足す
5. **チャットに出す**: 提案の要点(タイトル案、勝てる理由、概要、構成案、出典)を、テーマごとに短くまとめて出し、続けて、下の **② インタビュー**の質問を出す。Kaz が1つ選ぶ。合わないときは、引き直す(選ばれなかった提案は、在庫を `idea` に戻して、提案ファイルを消す)

**提案に入れること**(`common.md` 2-1c, 2-1d):
- **見出し案は、ラベルではなく、問い・意外性・読者の場面・約束のどれか**にする。導入の場面案も1つ出す
- 説明が中心のテーマ(自動詞・他動詞、文法など)は、**身近な物の動きなどの具体例**で見せる案を出す
- 構成案の各見出しに、**問いの前に置く、日常の場面**を書く(体験 → 引っかかり → 問い。`common.md` 2-1d)。日常から遠い設定は、橋をかける場面も書く
- **体験談・意見が中心の記事**は、主張を1つに絞る。研究の詳しい中身(数字、限界)は別の記事に回す案にして、**`inventory.csv` に、その記事の行を足す**(status: idea、note に「〜の記事から回した」)。確認できていない主張を、事実のように書く案にはしない

**書いてはいけないもの**: 記事の本文、本文に使える完成した文章。例文の候補(日本語学習)は、素材として示してよいが、Kaz が使うかを決める。

## ② インタビュー(Kaz への質問)— 新しい流れ(2026-10-05 から)

提案(概要と構成案)を出したら、そのテーマで **Kaz にインタビューする**。Kaz の意見・好み・失敗・偏りが、記事の「面白い1点」の元になる。質問は、**チャットで、概要を1段落見せてから、番号つきで出す**。

**質問の作り方**:
- **5〜8問**。1問ずつ、短く、答えやすく。「はい/いいえ」で終わる問いより、「どう思う?」「なぜ?」「いちばん〜なのは?」の形
- 狙いは、**記事を面白くするもの**: ①世間で言われていることへの「それ違うでしょ」、②自分がやってみて、うまくいかなかったこと・意外だったこと、③初心者に最初に言いたい一言、④たとえるなら、⑤このテーマの「好きな所・嫌いな所」。体験談の候補(記録がないもの)の確認も、ここに入れる
- 正解を問う質問(事実のクイズ)はしない。事実は、Claude が出典を開いて確かめる
- テーマが歴史や技術でも、「どこで引っかかったか」「どう思うか」を聞く
- 質問のあとに、「答えにくいものは飛ばして」と一言添える

**答えをもらったら**:
- Kaz の答えを、**personal-brain に記録**する(`add_persona_entry`。意見は kind: `insight`、出来事は `event`、source: `claude_code`、theme: `learning` など。Kaz が言った数字・固有名・時期だけ書き、足さない)
- 提案ファイル(`planning/.../proposals/<slug>.md`)の「インタビュー」の節に、質問と答えを貼る
- 答えが「ない」「分からない」の質問は、その体験なしで組む。**作り話で埋めない**
- 答えが足りなければ、追加で質問してよい(ただし、しつこくしない)

次に、`manavillage-review` の「新しい流れ」(④〜⑦)に進む。
