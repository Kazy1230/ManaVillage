`web/content/planning/common.md` の 2-1 と、対象の科目の文書(英語学習 `workflow.md` / 日本語学習 `japanese/workflow.md`)に従う。**記事の本文は書かない。**

Kaz が科目と本数を言っていればそれに従う。言っていなければ、各科目3テーマ。`web/` でコマンドを実行する。

1テーマごとに:

1. **抽出**: `node scripts/pick-topic.mjs <english|japanese>`(在庫から無作為。Kaz の確認はいらない)。topic-map を読んで重複するなら、在庫の行を `skip`(`note` に理由)にして引き直す
2. **調べる**:
   - 主キーワードで実際に検索し(日本語学習は英語で)、上位の記事は何か、何が足りないかを確かめる。上位が大手や公式で埋まっていて、切り口を変えても勝てない語なら、`skip` にして引き直す
   - 根拠にできる出典(研究の要旨、文法なら科目の文書が認める資料)を、**原典を開いて確認**する。確認できた内容と URL を書く。確認できなかったものは、そう書く
   - 英語学習は、personal-brain の `search_persona`(theme: learning)と `content/materials/` で、Kaz の過去の考えや体験を探し、示す(使うかは Kaz。体験を書き足さない)
   - 同じ科目の直近5本の見出しを読み、似すぎない構成にする(記事が少ないうちは、あるだけ)
3. **提案を書く**: `web/content/planning/proposals/<slug>.md`(日本語学習は `japanese/proposals/`)。書くこと: 仮タイトル案2〜3個、主キーワード、検索意図、想定読者(日本語学習はレベル)、勝てる理由(上位記事にない情報を最低1つ)、概要(3〜5行)、構成案(決まった型は使わない)、各見出しで使える具体例・例え話・小ネタの案、出典(確認済み)、サムネと図の案、内部リンクの候補
4. **登録**: 在庫の行を `selected` にして slug を書く。topic-map に `proposed` で行を足す
5. **チャットに出す**: 提案の要点(タイトル案、勝てる理由、概要、構成案、出典)を、テーマごとに短くまとめて出す。Kaz が1つ選ぶ。合わないときは、引き直す(選ばれなかった提案は、在庫を `idea` に戻して、提案ファイルを消す)

**書いてはいけないもの**: 記事の本文、本文に使える完成した文章。例文の候補(日本語学習)は、素材として示してよいが、Kaz が使うかを決める。
