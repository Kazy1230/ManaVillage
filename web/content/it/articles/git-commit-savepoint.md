Gitを使い始めると、最初に出てくるのが「コミット」です。**Git のコミットとは**何なのか、言葉だけだとつかみにくいですよね。この記事では、ゲームのセーブポイントにたとえて、コミットで何が残るのかと、いつコミットすればいいのかを説明します。

## コミットは「セーブポイント」

<div class="analogy"><span class="lbl">たとえるなら</span><p>ゲームで、ボス戦の前にセーブしておくと、負けてもそこからやり直せます。コミットも同じで、ファイルの状態をその時点で記録しておくと、あとでその状態に戻ったり、何を変えたかを見比べたりできます。これは仕組みをつかむためのたとえで、細かい動きまで同じという意味ではありません。</p></div>

コミットには、ファイルの中身のほかに、「誰が」「いつ」「何のために」変えたかを書いたメッセージが一緒に残ります。

## コミットまでの2つの手順

コミットは、次の2つの手順で行います。

1. `git add` で、記録したい変更を選ぶ
2. `git commit` で、選んだ変更をメッセージ付きで記録する

```
git add index.html
git commit -m "トップページの見出しを直す"
```

`git add` は「セーブする荷物を選ぶ」、`git commit` は「セーブボタンを押す」と考えると分かりやすいです。

## いつコミットすればいい？

目安は「ひとつの区切りがついたとき」です。見出しを直した、ボタンを1つ足した、のように、メッセージを1行で書ける単位にすると、あとで見返したときに分かりやすくなります。

## まとめ

まずは、何か1つ変えるたびに `git add` と `git commit` をしてみてください。コミットしてみて分からなかったことは、コメント欄で聞いてください。
