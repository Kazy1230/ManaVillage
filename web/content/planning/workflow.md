# 英語学習(日本語で書く)の記事制作ルール

日本語話者に向けて、英語の勉強方法・英文法・似た言葉・フレーズ・試験対策を書く記事(`/articles/...`)のルール。
**流れと役割分担(Kaz が書く、Claude は提案・確認・イラスト・公開)は `planning/common.md`**。記事の作業をするときは、`common.md` とこの文書の2つを読む。

---

## 0. 読者と書き方

- 読者: 英語を学ぶ日本語話者。中学生〜社会人、初心者〜上級者。記事ごとに想定読者を決める
- 文体・分量・構成は、Kaz が決める。目安は、5,000字前後(内容が足りなければ短くてよい)
- 個人ブログに見える言い方(「Kazです」「僕の学習メモ」「Kaz式」)は、囲みの外では避ける(機械チェックが見つける)。運営者の話は、囲みの中に書く

## 1. 素材庫と、運営者の体験

- **体験談は、Kaz の本当の体験だけ**。Kaz の記事では Kaz 自身が書く。**白河雪菜の記事では、Claude が、Kaz の体験を雪菜の話として語り直す**(`common.md` 5章)。囲みを使うと読者に伝わりやすい(下の「書き方の約束」)。体験談を使う記事は `type: experience`、使わない記事は `type: general`
- Claude は、**提案のとき**に、personal-brain(MCP サーバー)と `content/materials/` から、テーマに関係する Kaz の過去の考えや体験を探し、「こんな体験が使えるかも」と**示す**。使うかどうかと、書き方は Kaz が決める。Claude が体験談を書き足すことはしない
- 学習と関係のない私的な内容(恋愛、人間関係、お金、健康、仕事の愚痴)は、素材として示さない
- Kaz が話した、長く覚えておく価値のある考えや体験は、personal-brain に記録する(Claude の仕事)

## 2. 在庫の中身

`planning/inventory.csv`。分類: 勉強法、勉強法(読者別)、試験、英文法、似た言葉(4つの層)、前置詞・句動詞。テーマの抽出は `common.md` 2-1。

## 3. 提案で確認すること(Claude)

`common.md` 2-1 に加えて:

- 勉強法・体験に近いテーマでは、personal-brain に関連する素材があるかを調べ、あれば示す(使うかは Kaz)
- 似た言葉の記事は、層(①〜④)と、「機能のハブ/比較/1つの言い方」のどれかをはっきりさせる。同じ層の他の記事と重ならないようにする
- 読者違いの記事は、`common.md` 1章の2つの条件(検索の言葉が違う、中身が3つ以上変わる)を満たすことを、提案に書く
- 勉強法の研究に触れそうなテーマは、論文の要旨を確認し、確認できた内容と URL を示す

## 4. 確認で足す項目(Claude)

`common.md` 2-3 に加えて:

- 英文の例文と、その日本語訳が正しく、自然か
- 研究・統計の記述が、原典と合っているか(数字、対象、結論の強さ)
- 個人の意見や方法論が、一般的な事実のように書かれていないか(「運営者の意見・体験」と分けて書かれているか)。書き方は Kaz が決める。指摘するだけ
- `type` と囲みの食い違い(`experience` なのに囲みがない、`general` なのに囲みがある)

## 5. 機械チェック(`check-article.mjs` が見る項目)

- frontmatter: 必須の項目、slug とファイル名の一致、type と status の値、公開済みなら publishedAt、`experience` なら materialsUsed(Kaz 本人の体験なら `運営者本人の体験` と書く)
- description: 90〜150字(外れると「要確認」)
- タグ: 3〜5個。新しいタグは「要確認」。主キーワードをそのままタグにしていないか
- title と description が、ほかの記事と同じでないか
- 見出し: h1 がない、h2 より前に h3 がない、階層が飛んでいない
- 画像: alt、ファイルの存在。サムネ(`core.webp`)を本文に書いていたら不合格
- 内部リンク(`/articles/<slug>`): リンク先と related が公開済みか(本数の不足は、公開済み記事が3本未満のあいだ「要確認」)
- 主キーワードの語が、title と導入(最初の h2 より前)にすべて入っているか
- 本文が2,500字未満なら「要確認」。「Kazです」「僕の学習メモ」「Kaz式」がないか。「僕」は「要確認」
- `experience` に `voice` の囲みがあるか。`general` に `voice` がないか
- topic-map に行があり、主キーワードが一致しているか。ほかの記事と主キーワードが重なっていないか

## 6. frontmatter(Claude が組み立てる)

```yaml
---
title: ""              # Kaz が選んだ題名。検索意図が伝わる言葉と、主キーワードを入れる
description: ""        # 120字前後。Claude が案を出し、Kaz が決める
slug: ""               # 短い英語のスラッグ。科目をまたいで重複させない
type: general          # general / experience
status: draft          # draft / published
publishedAt: ""
updatedAt: ""          # 書き直したとき
primaryKeyword: ""     # ただ1つの検索語。topic-map と一致させる
searchIntent: ""
targetReader: ""
hub: ""                # topic-map のハブ名
tags: []               # 既存のタグから3〜5個
coreIllustration: core.webp
coreIllustrationAlt: ""
related: []            # 公開済みの記事の slug(2〜3本)
sources: []            # 確認した出典「著者(年). タイトル. 掲載誌」
materialsUsed: []      # experience では必須(Kaz 本人の体験なら「運営者本人の体験」)
keyword: ""            # カードに大きく出る短い英語
phrases: []            # 任意。最新記事のときトップで切り替わるフレーズ(key / rest / ja)
---
```

## 付録: manavillage.online での実装

### 置き場所

| 項目 | このサイト |
|---|---|
| 記事 | `web/content/articles/<slug>.md` |
| 提案 | `web/content/planning/proposals/<slug>.md` |
| イラスト | `web/content/illustrations/<slug>/`(サムネは `core.mjs`、本文の図は `fig-1.mjs` など)→ `node scripts/illustrate.mjs <slug>` で webp を書き出す |
| 確認担当 | `.claude/agents/manavillage-checker.md`(別のエージェントとして起動する) |

### コマンド(`web/` で実行)

- テーマの抽出: `node scripts/pick-topic.mjs english`
- イラストの書き出し: `node scripts/illustrate.mjs <slug>`
- 機械チェック: `node scripts/check-article.mjs <slug>`

### Kaz の書き方の約束(これだけ守れば、あとは自由)

Kaz は、ふつうの Markdown で書く。次の4つだけ、決まった書き方がある。Claude が、保存するときに機械的に変換する(言葉は変えない。変えた所は報告する)。

- 見出し: `##` から始める(h1 は題名から自動で作られる)
- 例文: 引用(`> `)で書く。英文の行、日本語訳の行の2行。間違い例は、英文の行の前に `NG: ` を付ける → 例文ボックスに変換される
- 蛍光ペン: `==語句==`
- 運営者の体験・意見: 段落の前に `【運営者の体験】`(意見なら `【運営者の意見】`)と書く → 囲みに変換される
- 図が欲しい所: `[図: こんな図が欲しい]` → Claude が描いて、画像に置き換える
- 内部リンク: `[記事のタイトル](/articles/<slug>)`(公開済みの記事だけ)。リンクを張ると段落の直後に埋め込みカードが出るので、1段落のリンクは1〜2本まで

## 新しい流れと書き方(2026-10-05 から)

`common.md` の 2-0(インタビュー → 記事化 → 面白くする編集者 → 承認 → 公開)と 2-1d(書き方)に従う。英語学習で特に守ること:

- **似た言葉・文法の記事は、「身近な一言で理由を言い切る → 対比 → 変な文で体感 → 日本語から英語へつなぐ」の型**(end と finish、rise と raise の記事が手本)。辞書の語釈や規則の紹介から入らない
- **日本語の感覚を使う**。日本語に同じ区別があるなら(自動詞・他動詞、「する」の使い分け)、先に日本語で体感させてから、「英語も同じ仕組み」とつなぐ。日本語の文法について言い切るときは、観察できる範囲にとどめる(「『た』は〜のしるし」のような、確認できない定義をしない)
- **インタビューでは、「困ったことがあるか・ないか」と「実際にどんな言葉を、どんな場面で」を必ず聞く**(make と do の記事で、いちばん効いた質問)
- 例文のうち、辞書・出典にあるものと、自作のものを混ぜて「辞書に載っている」と書かない
