# 日本語学習(英語で書く)の記事制作ルール

英語話者に向けて、日本語の文法・助詞・似た言葉・丁寧さ・フレーズ・学習法を英語で解説する記事(`/en/japanese/...`)のルール。
**共通のルール(流れ、重複の判定、例え話と小ネタ、共通のチェック項目)は `planning/common.md`**。記事を作るときは、`common.md` とこの文書の2つを読む。英語学習の文書(`planning/workflow.md`)は読まない。

---

## 0. 目的と読者

- 読者: 日本語を学んでいる、英語で読める人。**対象レベルは絞らない**。記事ごとに、初級・中級・上級のどれ向けかを決めて、レベルに合わせて書く(Kaz 決定)
  - 同じテーマでも、レベルによって検索の言葉と知りたいことが違うなら、レベル別に記事を分けてよい(`common.md` 1章の「重複の判定基準」)。レベル別の記事どうしはリンクする
  - レベルは `targetReader` に書き、タグにも `Beginner` / `Intermediate` / `Advanced` のどれかを入れる
  - 例文の漢字や語彙は、そのレベルに合わせる(初級向けに難しい語彙を混ぜない)
- 記事が答えること: 「この2つの違いは何か」「この形はいつ使うか」「なぜこれは間違いか」
- 価値の出し方: 教科書の説明の言い換えではなく、**身近な例え話**と、**使う場面が浮かぶ例文**と、**学習者が実際にやる間違い**で、腹落ちさせる
- 検索は英語で行われる(例: `wa vs ga`、`difference between miru and mieru`、`te shimau meaning`)。主キーワードも英語で決める

## 1. この科目の基本

| 項目 | 日本語学習 |

## 2. 記事の種類と、それぞれが答えること

**決まった構成(型)は使わない**(2026-10-02 Kaz 決定。同じ構成の記事ばかりになると、つまらないため)。下の「答えること」をすべて押さえれば、見出しの順番や見せ方は、テーマごとに自由に考える。同じ科目の直近5本と、見出しの流れが似すぎないようにする(`common.md` 2-2)。

| 種類 | 例 | 記事が必ず答えること |
|---|---|---|
| 助詞 | は vs が、に vs で | それぞれの働き / どちらを使うかの決め方 / 学習者がよくやる間違い |
| 文法の形 | 〜てしまう、〜ている | 意味(意味が複数あれば全部)/ 作り方(接続)/ 使う場面と使わない場面 |
| 似た言葉(① 似た単語) | 見る / 見える / 眺める | それぞれの意味と使う場面 / 置き換えると変になる例 |
| 機能の言い換え(②) | 依頼の言い方、謝り方 | その目的を果たす言い方の一覧 / くだけた〜丁寧の段階と、使う相手・場面 |
| 丁寧さ・場面(③) | です/ます と普通形、敬語 | 誰に・どんな場面で使うか / 間違えたときに相手がどう感じるか |
| 母語からのずれ(④) | "I’m sorry" と すみません | 英語の言葉をそのまま訳すと、何がずれるか / 代わりの言い方 |
| 決まった言い方・場面のフレーズ | いただきます、お店で | 意味と、使う場面 / 返し方 |
| 学習法 | 漢字の覚え方、JLPT の勉強 | 具体的な手順 / つまずく所と対処 |

- **1記事1テーマ**。広い記事(「助詞のまとめ」など)は、個別の記事ができてから、ハブ記事として作る
- 似た言葉・フレーズは、「機能のハブ(言い方の一覧)→ 2〜3語の比較 → 1つの言い方」の、どの記事なのかをはっきりさせる(`common.md` 2-1)
- 30秒の要点(`.points`)、比べる表、小テストは、使ってもよい道具。毎回入れる決まりではない

## 3. 書き方

### 英語の文章

- やさしい英語で、短い文で書く。文法用語を使うときは、最初に一言で説明する(例: `particle — a small word that shows the role of the word before it`)
- つづりは **アメリカ英語**にそろえる(Kaz 決定。例: color、favorite、practice、realize)
- 説教にならず、親しみやすく。導入は短く、最初の数行で何が分かるかを示す(`common.md` 2-4)

### 日本語の例文

- **自然な日本語だけ**を書く。教科書的すぎて、実際には言わない文は避ける
- 1つの例文に、学んでほしいことは1つ。ほかの難しい文法や、むずかしい漢字を混ぜない
- 例文の場面は、読者が想像しやすい日常(学校、仕事、買い物、友達、家族、旅行)
- 間違い例(NG)は、**はっきり誤りと言えるもの**だけ。「間違いではないが不自然」は NG にせず、本文で説明する
- 文法の説明が正しいかは、**ネットで原文を確認できる、信頼できる資料**で確かめ、`sources` に書く。確認できない説明は書かない(Kaz 決定)
  - 使ってよい: 国語辞典(コトバンクに載っている『デジタル大辞泉』など)、文化庁の資料(敬語は『敬語の指針』)、国立国語研究所の資料、JLPT の公式サイト(レベルの説明)、国際交流基金の日本語教育の資料(『日本語教育通信』など。2026-10-02 に Kaz が追加を承認)
  - 根拠にしない: 他の学習ブログ、Q&A サイト、掲示板、AI の答え。テーマや「学習者がどこでつまずくか」を調べるのには使ってよい

### ルビ(ふりがな)

- 本文、title、description、例文(phrases を含む)の **漢字すべて**に、記法 `{漢字|かんじ}` で読みを付ける
- 読みは、その文での読み方にする(例: `{今日|きょう}`、`{明日|あした}`)。熟語は熟語ごとに付ける
- `<ruby>` タグを直接書かない(記法にそろえる)
- 画面では最初から表示し、読者が記事ページの切り替えで消せる

### ローマ字

- **修正ヘボン式**で書く。助詞の は・を・へ は、発音どおり `wa`・`o`・`e`
- 長音は、**長音記号(マクロン)を使う**(Kaz 決定)。例: `gakkō`(学校)、`Tōkyō`、`kūkō`(空港)、`okāsan`(お母さん)、`onēsan`(お姉さん)
  - おう・おお → `ō`、うう → `ū`、ああ → `ā`、ええ → `ē`
  - いい は `ii`(例: `oishii`)、えい は `ei`(例: `gakusei`、`sensei`)のまま書く
  - 外来語の長音(ー)も記号で書く(例: `kōhī`)
- 例文の下に必ず付ける。本文中で日本語の言葉を出すときは、初出だけ `は (wa)` のように付ける

### 部品(記法)

```html
<div class="points"><span class="lbl">IN 30 SECONDS</span>

- 要点を3つまで

</div>

<div class="analogy"><span class="lbl">THINK OF IT LIKE THIS</span><p>例え話。最後に「たとえであって、すべての場合のルールではない」ことを一言そえる</p></div>

<div class="example"><span class="lbl">EXAMPLE</span><span class="jpx">{私|わたし}<mark>は</mark>{学生|がくせい}です。</span><span class="ro">Watashi wa gakusei desu.</span><span class="tr">I’m a student.</span></div>

<div class="ex-pair">  <!-- 2つ並べる(質問と答え、NG と OK) -->
<div class="example ng"><span class="lbl">NG</span>…<span class="why">なぜだめか(1文)</span></div>
<div class="example ok"><span class="lbl">OK</span>…</div>
</div>
```

- 比べる表は、Markdown の表で書く(サイトの表の見た目になる)
- 蛍光ペン: `==…==`

### 例え話と小ネタ

- `common.md` 2-4 のルールに従う。加えて:
  - 例え話は、**英語圏の読者にも通じる日常**を使う(日本だけの習慣を前提にしない)
  - 「日本人は〜」「外国人は〜」のような、国や文化の決めつけをしない
  - 日本の文化や習慣を紹介するときは、事実として確認できることだけ書く

### イラスト

- サイト共通の画風(白い背景、ゆるいクレヨンの絵。`common.md` 2-4)。和の小物(鳥居、桜、のれん、茶碗など。`doodle.mjs` の `torii`、`sakura`)を入れてよい
- **絵の中の日本語には、ルビを付けない**(Kaz 決定)。代わりに `coreIllustrationAlt` に英語で説明を書く

## 4. 流れ

`common.md` 2章の流れどおり。この科目では:

1. **テーマを選ぶ**: `node scripts/pick-topic.mjs japanese`(在庫から無作為。Kaz の確認なし)。主キーワードは英語の検索語。選んだら `planning/japanese/topic-map.md` に行を足す
2. **アウトライン**(`planning/japanese/outlines/<slug>.md`。決まった型は使わない)→ **企画チェック**(別エージェント。`common.md` 2-3 と5章)
3. **本文とイラスト**(`content/japanese/articles/<slug>.md`、`status: draft`)
4. **機械チェック**: `node scripts/check-article.mjs <slug>`(7章)
5. **本文チェック**(別エージェント。`common.md` 2-6 と6章。日本語の自然さも、ここで確認する)
6. **Kaz の確認** → 承認されたら公開。ローカルの URL は http://localhost:3000/en/japanese/articles/<slug>

## 5. 企画チェックで足す項目

`common.md` 2-3 に加えて:

- [ ] 記事のレベル(Beginner / Intermediate / Advanced)が決まっていて、テーマがそのレベルの読者に合っているか
- [ ] 英語圏の上位記事(主キーワードで英語で検索)と比べて、上位記事にない情報の候補があるか
- [ ] 文法の説明の根拠になる資料(3章「使ってよい資料」)が、実際に見つかっているか。見つからない説明を書く計画になっていないか
- [ ] 例文の候補が、自然な日本語で、そのレベルに合った語彙と漢字か
- [ ] 2章の「記事が必ず答えること」が、アウトラインで押さえられているか
- [ ] 似た言葉・フレーズの記事なら、「機能のハブ/比較/1つの言い方」のどれかがはっきりしていて、他の記事と重ならないか
- [ ] 小テストの案があるなら、場面が書かれていて、正解が1つに決まるか

## 6. 本文チェックで足す項目

`common.md` 2-6 に加えて:

- [ ] 日本語の例文が自然か(実際に言うか、場面に合うか)
- [ ] 文法の説明が正しいか。例外があるのに言い切っていないか(「always」「never」に注意)。説明が出典で裏付けられているか
- [ ] NG 例が、本当に誤りか(不自然なだけのものを NG にしていないか)
- [ ] ルビの読みが、その文脈で正しいか
- [ ] ローマ字の表記が3章のルールどおりか(長音記号、助詞の wa/o/e)
- [ ] 例文の英訳が、日本語と同じ意味か(ニュアンスを足したり、落としたりしていないか)
- [ ] 英語の文章が自然で、むずかしすぎないか。アメリカ英語のつづりか
- [ ] 例え話が、英語圏の読者にも通じる場面か。国や文化の決めつけがないか
- [ ] 2章の「記事が必ず答えること」を、すべて押さえているか
- [ ] 小テストがあるなら、正解が1つに決まるか
- [ ] JLPT のタグを付けているなら、本文で「公式の N4 文法」のように書いていないか(10章)

## 7. 機械チェック(`check-article.mjs` が見る項目)

- frontmatter: 必須の項目、slug とファイル名の一致、status の値、公開済みなら publishedAt
- **type が general であること**
- **ルビ**: title、description、本文、phrases の漢字に、すべて読みがあるか(記法 `{漢字|かんじ}`)。`<ruby>` を直接書いていたら「要確認」
- **タグ**: 10章の一覧にあるものだけ。3〜5個。レベルのタグがちょうど1つ。JLPT のタグは0〜1つ
- **ハブ**: Particles / Grammar / Synonyms / Politeness / Phrases のどれか
- description: 英語で110〜160文字(外れると「要確認」)
- 見出しの階層、画像の alt とファイル、核のイラストが本文に入っているか
- 内部リンク(`/en/japanese/articles/<slug>`)と related が公開済みの記事か。本数の不足は、この科目の公開済み記事が3本未満のあいだ「要確認」
- 主キーワードの語が、title と導入にすべて入っているか(大文字小文字は区別しない)
- 本文が800語未満なら「要確認」
- slug が、ほかの科目の記事と重複していないか
- `planning/japanese/topic-map.md` に行があり、主キーワードが一致しているか

## 10. ハブとタグ(固定の一覧。Kaz 決定)

ここにないハブやタグは作らない。足したいときは Kaz に確認する。

- **ハブ(大分類。記事ごとに1つ)**: `Particles`(助詞)、`Grammar`(文法の形)、`Synonyms`(似た言葉)、`Politeness`(丁寧さ・敬語)、`Phrases`(決まった言い方)
- **タグ(記事ごとに3〜5個)**
  - ハブ: `Particles` `Grammar` `Synonyms` `Politeness` `Phrases`
  - レベル(1つ): `Beginner` `Intermediate` `Advanced`
  - JLPT(0〜1つ): `N5` `N4` `N3` `N2` `N1`
  - そのほか: `Verbs` `Adjectives` `Conversation` `Business`
- **JLPT タグの付け方**
  - JLPT は、レベルごとの単語・漢字・文法の公式リストを公開していない(JLPT 公式サイトの FAQ。https://www.jlpt.jp/e/faq/ で確認済み)。教科書や学習サイトの「N4 文法」の一覧は、それぞれ独自の目安
  - そのため、タグは「そのレベルでよく学ぶ」という目安として付け、本文でも「N4 の公式文法」とは書かない。書くなら `commonly studied around N4` のように書く
  - 迷うとき、レベルに関係しない記事には付けない
  - レベルとの対応の目安: N5・N4 = Beginner、N3 = Intermediate、N2・N1 = Advanced
