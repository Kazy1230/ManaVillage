- [ ] **プライバシーポリシーと利用規約の文面を、公開前に専門家(弁護士など)に確認してもらう**(個人情報保護法の対応範囲など。今は運営者向けの下書きとして公開している)
- [ ] **広告を導入するとき**: プライバシーポリシーの5章を更新する(広告サービスの名前、取得される情報、無効にする方法)。AdSense の場合は、`ads.txt` の設置と、Cookie の同意の取得方法(同意バナーなど)も検討する
- [ ] **記事の署名と AI の関与**: 記事には「Kaz」の署名(`K` のアバター)が出ているが、制作には AI(Claude)の支援を使っている。「まなビレッジとは」には「公開前に運営者が確認する」とだけ書き、執筆者を断定していない。署名の書き方と、AI の関与を書くかどうかは Kaz が決める
- [ ] **アカウント削除の手順と DB の設計**: 現在の設計では、ユーザーを削除すると、その人のコメント・スレッド・書き込みが一緒に消える(外部キーの `on delete cascade`)。さらに、**その人が作ったカテゴリを使う他の人のスレッドも、カテゴリごと消える**(`board_categories.created_by` も cascade のため)。削除依頼を受けたときは、先にそのユーザーが作ったカテゴリがないか確認する。恒久対応は、`created_by` を `on delete set null` に変える(本番 DB の変更なので、Kaz の確認後に行う)
- [ ] お問い合わせ先のメールアドレス(`xenon.english@gmail.com`)を公開したので、迷惑メールが増えたら専用のアドレスに切り替える(`web/src/lib/site.ts` の `CONTACT_EMAIL`)
