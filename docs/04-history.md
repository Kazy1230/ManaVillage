## 2026-09-27〜28: モック作り

- 出発点は `docs/01-requirements.md`(要件定義書 v1.2)。コンセプトは「Kaz が英語学習の記事を投稿し、学習者がアカウントを作って交流できる場」
- 「Figma 以外のデザインツールでモックを」という依頼で、いくつか試した
  - **Penpot**: アカウントを作り、SVG をインポートして画面を組む方法を試したが、Kaz が「手作業ではなく AI に作ってほしい」と中止
  - **Uizard(Autodesigner)**: プロンプトから画面を生成。サイト名から RPG ゲーム風の内容が混ざり、無料プランは5画面まで。中止
  - **Claude が HTML で直接モックを作る**方式に決定
- モックは3回作り直した
  1. v1: 記事メインのサイトに。暗めの紺と、画面切替の黒いバー
  2. v2(Kaz の意見:「もっとモダンに、余白を使って、ごちゃごちゃしすぎ、色が暗い、ナビをまとめて」): 白背景、余白を広く、ナビは「記事・掲示板・ログイン」の3つに
  3. v3(「もっと動かしていい。境界が分かりづらいので UI/UX のプロとして」): 淡いグレーの地に白いパネル、区切りを明確に。フレーズのカルーセル、蛍光ペンのアニメーション、スクロールで現れる要素、ティッカー など
- v3 を Claude の Artifact と Vercel(`manavillage-mock`)に公開。これがデザインの基準(`docs/05-design.md`)。ファイルは `docs/archive/mock/`

## 2026-09-29: 技術の決定とバックエンド実装

- 「Vercel 無料プランで Next.js と FastAPI はできない？」→ できるが、**Next.js + Supabase(FastAPI なし)を推奨**し決定
  - 要件は CRUD 中心。Supabase の認証と RLS で足りる。アプリが1つで管理が楽
  - 将来の拡張(学習者の画面、学習データの分析)も、Supabase は普通の Postgres なので対応できる。Python が必要になったら後から足す
- 掲示板のカテゴリ(要件の未決定事項)は **学習者が自由に作れる**に決定
- Next.js 16 で実装(`docs/02-architecture.md`)。Supabase のプロジェクトは Kaz が作成し、SQL を実行
- Vercel にデプロイ(最初は `manavillage.vercel.app`)。Resend のキーも設定

## 2026-09-30: 独自ドメインと SEO
