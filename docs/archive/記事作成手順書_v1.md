# まなビレッジ 記事作成手順書 v1.0

## 0. この手順書の目的と方針

記事を安定して量産するための手順。Claude が下書きから絵まで作り、Kaz が確認して公開する。

**サイトの戦略**
- **変な絵**：白い背景に、3歳児が描いたようなてきとうな絵。上手さより「ゆるさ」と「覚えやすさ」を優先する
- **身近な例**：日本で暮らす学習者の日常（コンビニ、電車、職場、LINE、家族など）に置き換えて説明し、親近感を持ってもらう

**大原則：既存記事の書き換えはしない**
- ネットの記事は「何がよく聞かれているか」「どこでつまずくか」を知るための**調査材料**として使う
- 1本の記事の文章・構成・例文を言い換えて使うことはしない。構成、例文、たとえ話、絵はすべて自分たちで作る
- 理由：①言い換えでも構成や流れが同じだと著作権侵害になりうる ②検索エンジンは既存記事の焼き直しを低く評価するので、集客の面でも逆効果

## 2. 工程1：テーマ出し

**テーマの種類（偏らないように回す）**
- 単語・表現の違い：「see / look / watch の違い」「maybe と probably」
- 場面の言い方：「〜してもいいですか」「断り方」「お礼の返し方」
- 文法のつまずき：「現在完了」「a と the」「前置詞 on / in / at」
- 日本人がやりがちなミス：「Me too の誤用」「I'm fine, thank you 問題」
- 発音・リスニング：「リンキング」「L と R」
- 勉強法：「英語日記の続け方」「シャドーイングの教材選び」

**選び方の基準**
- 学習者が実際に検索しそうか（「〜 違い」「〜 使い方」「〜 英語で」の形で検索されるもの）
- 1記事で「これだけ覚えればいい」という結論をひとつ出せるか
- 身近な例と変な絵にしやすいか
- 既存の記事と重ならないか（`web/content/articles/` を確認する）

**管理**
- テーマ候補は `documents/記事テーマ一覧.md` に「候補 → 執筆中 → 確認待ち → 公開済み」のステータス付きで記録する

---

## 3. 工程2：リサーチ

1. 学習者が使いそうな検索語で検索する（例：「see look watch 違い」）
2. 上位〜中位の記事を **3〜5本** 読む。1本だけに頼らない
3. 調査メモに次の点だけを書く（本文のコピーはしない）
   - どの記事にも書いてある基本の説明
   - わかりにくかった点、説明が足りない点、例文が不自然な点
   - 学習者がよく間違えるポイント
4. **事実確認**：意味・用法は英英辞典か大手の英和辞典で確認する（Cambridge、Oxford Learner's、Longman、ジーニアス など）。1つのブログ記事の説明だけで判断しない
5. 調査メモは公開しない。参照した URL は、あとで確認できるようにメモに残す

## 4. 工程3：構成づくり

調査した記事の構成は見ずに、白紙から作る。

**基本の型**
1. **つかみ**：身近な場面のちょっとした失敗・もやもや（例：「コンビニでレジ袋いりますかと聞かれて、とっさに英語が出ない」）
2. **結論**：この記事で覚えることをひとつ示す
3. **説明**：2〜4個の見出しに分ける。各見出しに例文を1〜2個入れる
4. **よくある間違い**：NG 例と正しい言い方
5. **まとめ**：箇条書きで3〜5行
6. **コメントへの誘導**：「あなたならどう言いますか？」など、コメントしたくなる問いかけ

**例文のルール**
- 調査した記事の例文は使わない。自分で作る
- 身近な場面を使う（電車、コンビニ、職場、家族、友だちとの LINE など）
- 1文は短く、中学英語＋今回の表現だけで作る
- 不自然な英語になっていないか、辞書の用例と照らして確認する

## 5. 工程4：執筆

**文体とレベル**
- 「です・ます」調で、話しかけるように。先生っぽくなりすぎない
- 想定読者：英語学習をやり直している社会人・大学生（中学〜高校英語レベル）
- 分量：2,000〜3,500字（5〜8分で読める長さ）
- 専門用語は使うなら一言で説明する（例：「仮定法（もしもの話をするときの形）」）

**ファイルの置き場所と名前**
- `web/content/articles/<スラッグ>.md`
- スラッグは英小文字とハイフン（例：`see-look-watch.md`）。URL になるので公開後は変えない

**フロントマター（ファイル先頭）**
```yaml
---
title: 記事タイトル（32字前後。検索語を前半に入れる）
date: 2026-10-01
tags: [単語の違い, 会話]        # 1〜3個。既存タグを優先して使う
summary: 一覧やトップに出る説明文（60〜80字）
keyword: see / look / watch     # 記事カードに大きく出る英語（短く）
phrases:                        # 任意。最新記事のときトップで順番に表示される
  - { key: "look at", rest: "this picture!", ja: "この写真見て！", level: "ふつう" }
---
```

**本文で使える書き方**
- 蛍光ペン：`==Can I==`
- 例文ボックス：
  ```html
  <div class="example"><span class="lbl">EXAMPLE</span><span class="en"><mark class="hl">Can I</mark> borrow your pen?</span><span class="ja">ペン借りていい？</span></div>
  ```
- NG ボックス：上の `class="example"` を `class="example ng"`、`EXAMPLE` を `NG` にする
- 見出しは `##`（大見出し）と `###`（小見出し）だけ使う

**タグのルール**
- まず既存タグを使う（今あるもの：丁寧表現、ビジネス英語、会話、リスニング、発音）
- 新しく作るときは短い名詞にする（例：単語の違い、文法、前置詞、勉強法、旅行英語）
- 似たタグを作らない（「発音」があるなら「発音のコツ」は作らない）

## 6. 工程5：変な絵

**スタイル**
- 白い背景に、3歳児がクレヨンで描いたような絵
- 線はわざとガタガタにする。丸はゆがんでいてよい
- 色は2〜4色まで。黒の線＋差し色（青・黄・赤など）
- 人物は棒人間か、丸い顔に点の目
- 英語のフレーズを吹き出しで入れると、覚えやすくなる
- 上手に描かない。「ちょっと笑える」「なんか覚えてる」がゴール

**枚数と使いどころ**
- 1記事に1〜3枚
- 1枚目は冒頭のつかみの場面
- 2枚目以降は、違いを説明する見出し（例：see はぼんやり、look は目をこらす、watch はじっと追う）

**ファイル**
- 形式：SVG（軽くて拡大してもきれい）
- 置き場所：`web/public/articles/<スラッグ>/1.svg`、`2.svg` …
- サイズの目安：横 800 × 縦 500
- 本文への入れ方：`![絵の説明](/articles/<スラッグ>/1.svg)`
- 説明（alt テキスト）は必ず書く。目の見えない読者の読み上げ用なので、絵の内容を一文で（例：「電車で窓の外を眺める棒人間」）

**注意**
- 実在の人物、キャラクター、ロゴは描かない
- 絵の中の英語はスペルミスがないか確認する

## 7. 工程6：チェックリスト

Claude が確認してから Kaz に渡す。

- [ ] 意味・用法を辞典2つ以上で確認した
- [ ] 調査した記事と、文章・構成・例文が似ていない
- [ ] 例文が自然な英語で、身近な場面になっている
- [ ] 結論がひとつにしぼれている
- [ ] 変な絵が表示され、alt テキストが入っている
- [ ] タグは既存のものを優先し、3個以内
- [ ] タイトル・summary・keyword が入っている
- [ ] ローカルで表示を確認した（`web` フォルダで `npm run dev` → http://localhost:3000）
- [ ] ビルドが通る（`npm run build`）

Kaz が確認すること：
- [ ] 内容が正しく、Kaz 自身が書いたと言える内容になっているか
- [ ] Kaz 自身の体験・たとえ話を足すところはないか

## 8. 工程7：公開

Kaz の OK が出たら Claude が本番に反映する。

```bash
cd web
npx vercel deploy --prod --yes
```

公開後に、https://manavillage.vercel.app/articles/<スラッグ> で表示を確認する。

## 9. 量産のペース（目安）

- テーマ出しは10本単位でまとめて行い、Kaz が選ぶ
- 執筆は1回の依頼で1〜3本ずつ。まとめて作りすぎると確認が大変になるため
- 公開済みの記事が20本を超えたら、よく読まれている記事・コメントが多い記事の傾向を見て、テーマの選び方を見直す
